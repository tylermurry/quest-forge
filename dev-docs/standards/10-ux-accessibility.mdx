# UX and accessibility

The product exists for the people who use it, including those who use a keyboard, a touch
screen, a screen reader, or who see colour differently.

**Applies to:** any change to something a user sees, reads or operates.

## Rules

### UXA-1: Plain-language text

**Must.** Text shown to users is in plain language. A message about a problem says what
happened and what the user can do next, and never shows an internal code alone.

### UXA-2: Operable without a mouse

**Must.** Everything the change adds can be operated from the keyboard, and by touch where
the product supports touch.

### UXA-3: Not by colour alone

**Must.** Information is never carried by colour alone, and text meets the WCAG AA contrast
level.

### UXA-4: Destructive actions are safe

**Must.** An action that destroys the user's work can be undone, or asks for confirmation
first.

### UXA-5: Controls have accessible names

**Must.** Every interactive control has a name that assistive technology can read out.

### UXA-6: Verified in the running product

**Must.** A user-facing change has been run and looked at in the real product, not only
covered by tests. The description says what was checked.

### UXA-7: Consistent with what exists

**Should.** The change uses the product's existing words, patterns and components for
things the product already does.

### UXA-8: Every state is designed

**Should.** The user gets visible feedback for each action, and the loading, empty and
error states are designed, not left to chance.

### UXA-9: Comfortable to operate

**Should.** Touch targets are large enough to hit reliably, and motion respects the
user's reduced-motion setting.
