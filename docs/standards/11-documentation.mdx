# Documentation

Written knowledge is the project's memory. It is only useful while it matches the code.

**Applies to:** any change to behaviour, structure, commands or conventions that are
written down anywhere.

## Rules

### DOC-1: Update docs in the same change

**Must.** Documentation that describes what the change alters is updated in that change.
No document is left saying something untrue.

### DOC-2: Record decisions

**Must.** A new decision about the product or its design is added to the project's
decision log with an identifier and a status that says whether the owner confirmed it.

### DOC-3: Keep contributor instructions accurate

**Must.** Instructions for contributors, including instruction files read by AI, are
updated when the structure, commands or conventions they describe change.

### DOC-4: The documentation builds

**Must.** The documentation builds without errors and has no broken links.

### DOC-5: Document public interfaces where they are defined

**Should.** Anything others are meant to use says what it does, what it expects and what
it returns, next to its definition.

### DOC-6: Short, plain, with an example

**Should.** Documentation is in plain language, as short as it can be, and shows an example
where one helps.

### DOC-7: Say it once

**Should.** A fact is written in one place and linked to from others, not copied.
